# Agoryx — Product Brief

## Що таке Agoryx

Agoryx — це локальна площадка для спільної роботи кількох LLM-агентів і людини. Назва від грецького ἀγορά — публічний простір, де громадяни збирались щоб обговорювати і вирішувати разом.

Основна проблема: сьогодні робота з кількома LLM означає ручне копіювання тексту між додатками і повторне пояснення контексту. Agoryx замінює це однією спільною розмовою де агенти бачать повідомлення одне одного.

Ключова філософія: **Agoryx — це площадка, а не агент.** Agoryx не намагається замінити Claude Code, Codex, Gemini CLI чи будь-якого іншого агента. Він дає їм місце і протокол для співпраці. Brains залишаються у агентів, coordination — у Agoryx.

## Як це працює зараз (v0.3)

Agoryx — CLI-додаток який обгортає існуючі CLI-агенти (`claude -p`, `codex exec`). Користувач пише повідомлення, Agoryx збирає контекст з історії розмови (включно з відповідями інших агентів), і передає його цільовому агенту. Агент відповідає, відповідь зберігається в SQLite, і стає доступною для наступного агента.

Архітектура з трьох шарів:
- **Transport** — адаптери до CLI-агентів, парсинг stdout, нормалізація подій
- **Session** — кімнати, повідомлення, контекст-білдер, checkpoints, pinned context, memory
- **Orchestration** — 5 політик (manual, round-robin, auto, team, free)

Що реалізовано:
- 5 режимів оркестрації включно з autonomous team runtime
- Контекст-білдер з token budgeting, checkpoints, workspace awareness
- Проєктна пам'ять (.agoryx/memory.md)
- Per-agent git worktrees для безпечної паралельної роботи
- Crash recovery і session resumption
- 398 тестів, ~8300 рядків TypeScript

## Як продукт має виглядати в кінці (v1)

### Core: Room as a Service

Agoryx v1 — це **локальний сервіс** (daemon), який підтримує "кімнати" — persistent collaboration spaces з повною історією, контекстом і пам'яттю. Кімната — це не чат-вікно. Це робочий простір де зберігаються рішення, артефакти, контекст проєкту.

### Два способи підключення агентів

**1. Native mode (основний):** Agoryx виставляє стандартизований інтерфейс (MCP server, або інший протокол — потребує дослідження), до якого агенти підключаються самостійно. Користувач додає Agoryx в конфіг Claude Code чи Codex, і агент отримує tools для взаємодії з кімнатою: прочитати контекст, написати повідомлення, поділитись файлом. Агенти самі домовляються хто що робить.

**2. Direct mode (legacy/simple):** Поточний підхід — Agoryx сам запускає CLI-агентів і передає їм контекст. Для користувачів яким потрібен zero-config досвід.

### Ключові можливості v1

- **Room protocol:** Стандартизований набір операцій для участі в кімнаті (read, write, share, status). Достатньо простий щоб агенти могли ним користуватись без спеціального навчання.
- **Smart context delivery:** Замість raw history dump — розумно зібраний контекст з summaries, checkpoints і pinned blocks. Це core IP Agoryx і головна причина чому "просто shared файл" не працює.
- **Project memory:** Persistent знання про проєкт, рішення, артефакти. Зберігається між сесіями.
- **Multi-agent awareness:** Агенти знають хто ще в кімнаті, хто що робив, і можуть координуватись через повідомлення.
- **Local-first:** Все зберігається локально. Ніякого cloud, ніяких зовнішніх сервісів.
- **Agent-agnostic:** Будь-який агент який підтримує інтерфейс (MCP або інший) може стати учасником кімнати. Кожен новий агент на ринку — не конкурент, а потенційний учасник.

### Чого Agoryx НЕ робить

- Не замінює агентів. Не конкурує з Claude Code, Codex, Pi чи іншими.
- Не нав'язує workflow. Не має формального task management, voting, approval gates (крім team mode). Агенти домовляються між собою.
- Не потребує API-ключів. Працює з існуючими підписками через CLI або native інтеграції.

## Що потрібно дослідити

1. **Протокол підключення агентів.** MCP виглядає природним кандидатом (Claude Code і Codex обидва підтримують MCP clients), але чи є він найкращим вибором? Альтернативи: A2A (Agent-to-Agent protocol від Google), OpenAI Agents SDK, custom REST/WebSocket API, Language Server Protocol pattern, Unix pipes, або комбінація.

2. **Модель взаємодії через MCP.** Якщо MCP — які саме tools/resources/prompts виставляти? Як вирішити проблему identity (агент має приходити як конкретний учасник)? Як впоратись з обмеженнями MCP output size?

3. **Конкурентне середовище.** Хто ще будує multi-agent collaboration platforms? Що роблять CrewAI, AutoGen, LangGraph, Agency Swarm? Чим відрізняється підхід Agoryx (площадка vs orchestrated pipeline)?

4. **Практичні обмеження.** Контекстне вікно агентів обмежене. Кожен tool call до Agoryx — це витрата токенів на координацію замість роботи. Як мінімізувати цю "координаційну вартість"?

5. **Ринковий потенціал.** Хто цільовий користувач? Розробник який вже працює з Claude Code і Codex і хоче їх поєднати? Чи є достатньо таких людей? Яка альтернатива (manual copy-paste, bridge files)?
