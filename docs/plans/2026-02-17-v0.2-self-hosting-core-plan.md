# Agoryx v0.2 Plan: Self-Hosting Core (CLI-First)

## Summary
Agoryx v0.2 focuses on self-hosting core capabilities: agents should execute real development work in one shared session, not only chat.  
The target flow is a strict pipeline: `plan (claude) -> implement (codex) -> review (claude)`, with completion allowed only after passing checks and review.

## Scope
1. Add `team` orchestration mode with autonomous task pipeline.
2. Add agentic execution support for both `codex` and `claude`.
3. Add execution broker for checks, workspace snapshots, and safety handling.
4. Add persistent task protocol and task lifecycle state.
5. Keep CLI-first runtime (`agoryx chat`) with long-running sessions.
6. Keep one active autonomous task per room in v0.2.

## Out of Scope
1. Web UI.
2. Required daemon runtime.
3. Multi-user rooms.
4. Plugin marketplace/community adapter platform.
5. Auto commit/push/PR.

## Locked Decisions
1. v0.2 is self-hosting core, not web-first.
2. Runtime is CLI-first long session.
3. Agentic adapter support targets Codex and Claude parity.
4. Pipeline is fixed: `plan -> implement -> review`.
5. `done` is strict: requires green checks and review approval.
6. Safety policy is allowlist + hard deny for broker commands.
7. Dangerous internal command traces trigger `failed_safety` and stop task.
8. Resume after restart is manual (`/task resume`).
9. One active task per room.
10. DB migrations are automatic and idempotent at startup.

## Execution Design

### Team State Machine
1. `plan`: Claude creates structured plan.
2. `implement`: Codex edits files.
3. `checks`: broker runs configured check commands.
4. `review`: Claude approves or requests changes.
5. `done`: only after checks pass and review approves.
6. Stop conditions: `maxSteps`, `maxNoProgressSteps`, `failed_safety`, `/task stop`.

### Structured Control Envelope
Each team-stage response starts with:
```json
{"agoryx":{"decision":"approved|needs_changes|blocked|continue","summary":"...","nextStage":"plan|implement|checks|review|done"}}
```
Missing envelope handling:
1. One repair reprompt.
2. If still invalid: mark step as protocol failure.

### Execution Broker Responsibilities
1. Record workspace snapshot before and after each step.
2. Run check commands with timeout and output capture.
3. Emit `tool.call.started/completed` events.
4. Detect dangerous traces and stop task with `failed_safety`.

## Delivery Plan

## PR1: Agentic Foundation + Execution Broker
1. Add `agentic` adapter mode and workspace-aware adapter config.
2. Add execution modules:
   1. `internal/execution/broker.ts`
   2. `internal/execution/workspace.ts`
   3. `internal/execution/safety.ts`
3. Add tool-call event factories and payload support.
4. Enable agentic path in both Codex and Claude adapters.
5. Acceptance: agentic session can produce file changes and emit execution artifacts.

## PR2: Team Mode + Task Protocol
1. Add `TeamPolicy` and orchestrator factory integration.
2. Add `TaskService` in session layer.
3. Add task tables and persistence APIs.
4. Add `/task *` CLI command set.
5. Acceptance: full stage transitions persist and can be resumed manually after restart.

## PR3: Strict Gate + Review Loop
1. Implement mandatory checks stage (`npm run typecheck`, `npm test` by default).
2. Implement review decision loop (`needs_changes` returns to implement).
3. Enforce strict `done` gate.
4. Persist check records in `task_checks`.
5. Acceptance: task cannot reach `done` if checks fail or review is not approved.

## PR4: Guardrails + Long-Session Hardening
1. Add max step/no-progress guardrails.
2. Add deterministic stop behavior for dangerous traces.
3. Add robust recovery for interrupted active task sessions.
4. Acceptance: no infinite loops, consistent restart/resume behavior.

4. Integration test for full `plan -> implement -> checks -> review -> done`.
5. Integration test for `review -> needs_changes -> implement` loop.

## Acceptance Criteria for v0.2
1. `team` mode executes autonomous pipeline end-to-end.
2. `done` requires green checks and review approval.
3. Task state and artifacts survive restart.
4. Dangerous traces stop task with explicit failure reason.
5. Existing v0.1 behavior remains stable.

## Assumptions and Defaults
1. Default checks: `npm run typecheck`, `npm test`.
2. Default role mapping: plan=claude, implement=codex, review=claude.
3. One active autonomous task per room.
4. Team capability is available in v0.2 without extra feature flag.
5. Full low-level interception of every internal provider tool call is deferred; v0.2 uses detect-and-stop for dangerous traces.
