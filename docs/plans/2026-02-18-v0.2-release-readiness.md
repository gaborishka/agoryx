## Known Risks (Non-Blocking)

1. Upstream CLI protocol drift
- Codex/Claude event formats can change; mitigated by parser and adapter contract tests.

2. Team interrupt UX depends on terminal behavior
- Esc hotkey is TTY/raw-mode dependent; `/team interrupt` remains deterministic fallback.

3. Team output quality variance
- Runtime guardrails sanitize known noise patterns, but output style still depends on model behavior.

## Direction After v0.2 (Bridge-Free Track)

### Track A: Self-hosting workflow inside Agoryx
1. Add explicit "review/approve/apply" loop artifacts inside team runs (first-class patch/review events).
2. Persist structured decisions and TODOs in room state (not only text messages).
3. Add "runbook commands" for recurring dev actions (verify, smoke, release checks).

### Track B: Speed and stability
1. Add adapter-level telemetry (turn latency, timeout rate, restart count).
2. Add light benchmark command for cold vs warm turn latency in `cli` vs `agentic`.
3. Add crash-recovery replay check at startup for interrupted team runs.

### Track C: Usability
1. Add clearer in-chat progress summaries for long team runs.
2. Add optional compact mode for high-signal terminal output.
3. Add profile presets (`fast`, `balanced`, `strict`) for team limits/checks.

## Success Criteria for v0.3 Planning

- A daily coding session can be run end-to-end in Agoryx without manual Bridge relay.
- Team mode can produce, verify, and present a patch proposal with predictable handoff.
- Mean warm-turn latency and failure rate are measurable and trending down release-over-release.
