# Agoryx v0.3 (CLI-First) and v0.4 (MCP-First) Direction

Date: 2026-02-18  
Branch: `feat/v0.2`

## v0.3 Goal (Locked)

1. Bridge-free daily development using CLI only.
2. Claude Code level UX loop: `prompt -> plan -> execution -> verify -> handover`.
3. Reliability level suitable for real development work.

## v0.3 Scope (CLI-First)

1. Workspace-aware by default:
- Automatic git status/diff and file-map context in agent prompts.

2. Project memory:
- Persist key decisions, current state, and next actions across restarts.

3. Parallel agents safely:
- Task dispatch with workspace isolation via git worktrees.

4. Operational control:
- `status`, `logs`, `cancel`, `resume`, `retry`.

5. Predictable output:
- Clear plans, patch summaries, explicit failure reasons, stable handover format.

## v0.3 Out of Scope

1. Web UI (including read-only timeline) is intentionally excluded from v0.3.
2. Full MCP transport and full permission/audit system are deferred.

## v0.3 Definition of Ready

1. 5 working days of dogfooding without `bridge/*`.
2. Crash/restart preserves run/step/context state.
3. 2+ agents run in parallel without workspace conflicts.
4. Core CLI commands pass smoke/e2e checks consistently.

## v0.4 Direction (Preview)

`MCP-first Agoryx`: Agoryx acts as orchestration backend for MCP-capable clients (e.g., Claude Code, Codex), while CLI remains a fallback/admin interface.

Planned shape:
1. Daemonized runtime (`state + memory + orchestration + recovery`).
2. MCP tools for orchestration flows (`start/status/result/cancel/resume/retry`).
3. Policy enforcement and auditability as first-class features.
4. Backward compatibility with v0.3 state and workflows.

## Rationale

v0.3 focuses on guaranteed daily usability and Bridge removal with minimal architecture risk.  
v0.4 can then productize the same core as an MCP backend without re-solving reliability fundamentals.
