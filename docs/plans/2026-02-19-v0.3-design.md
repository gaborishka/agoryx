# Agoryx v0.3 Design — CLI-First Daily Workflow

Date: 2026-02-19
Status: Approved
Author: Claude (with Ivan review)

## Goal

Bridge-free daily development using CLI only. Reliability level suitable for real development work. 5 working days of dogfooding without `bridge/*`.

## Approach

Bottom-Up Layers (Approach A, with worktrees elevated before workspace context):

1. Memory Core (SQLite log + snapshot rebuild + crash replay)
2. Worktrees MVP (create/list/remove, agent-worktree lock, write-guardrails)
3. Workspace Context (standard: always-on + on-demand)
4. CLI Surface + `.agoryx/memory.md` autogen

## Definition of Ready

1. 5 working days of dogfooding without `bridge/*`.
2. Crash/restart preserves run/step/context state.
3. 2+ agents run in parallel without workspace conflicts.
4. Core CLI commands pass smoke/e2e checks consistently.

## Invariants (all sections)

1. `memory_log` is append-only, never edited or deleted.
2. `memory_snapshot` is engine-driven only, never written by agents or user directly.
3. Replay is idempotent (stable `event_id`, `INSERT ON CONFLICT DO NOTHING`).
4. No "smart" merge-policy in v0.3 — only deterministic retry/resume.

## Section 1: Memory Core

### SQLite Schema

Two new tables in `agoryx.db`.

#### `memory_log` (append-only semantic event log)

| Column | Type | Constraints | Description |
|--------|------|-------------|-------------|
| `id` | INTEGER | PK AUTOINCREMENT | sequence number |
| `event_id` | TEXT | UNIQUE NOT NULL | stable UUID for idempotent replay |
| `room_id` | TEXT | FK rooms(id) NOT NULL | room context |
| `timestamp` | TEXT | NOT NULL | ISO-8601 |
| `source` | TEXT | NOT NULL | `engine`, `adapter.codex`, `adapter.claude`, `user` |
| `event_type` | TEXT | CHECK(IN list) NOT NULL | see event types below |
| `payload` | TEXT | CHECK(json_valid) NOT NULL | event-type specific JSON |

Event types: `dispatch_start`, `dispatch_end`, `team_step`, `error`, `decision`, `note`, `cancel`, `retry`, `merge_attempt`, `worktree_create`, `worktree_remove`.

Insert dedup: `INSERT INTO memory_log (...) VALUES (...) ON CONFLICT(event_id) DO NOTHING`.

Separate from `events_log` — only semantic events, no `message.delta`.

#### `memory_snapshot` (engine-driven, rebuilt from log)

| Column | Type | Description |
|--------|------|-------------|
| `room_id` | TEXT PK | one snapshot per room |
| `current_goal` | TEXT | active goal/task |
| `active_branch` | TEXT | git branch name |
| `active_worktrees` | TEXT | JSON array of worktree assignments |
| `key_decisions` | TEXT | JSON array of decision strings |
| `blockers` | TEXT | JSON array |
| `next_actions` | TEXT | JSON array |
| `task_status` | TEXT | JSON object {task: status} |
| `last_log_id` | INTEGER | replay cursor — last log entry processed |
| `reducer_version` | INTEGER | schema version; mismatch triggers full replay |
| `updated_at` | TEXT | ISO-8601 |

### Crash Recovery

On startup: compare `MAX(id) FROM memory_log` vs `snapshot.last_log_id`. Gap → replay missing entries. `reducer_version` mismatch → full replay from id=1.

### Transactional Integrity

Snapshot update + log append always in the same SQLite transaction. Monotonic guard: new `last_log_id` must be > current `last_log_id`.

### Engine Integration

- After `dispatch_end`: auto-append log entry (agent, result, files touched)
- After `team_step`: auto-append with step details
- On checkpoint: rebuild snapshot from recent log window
- On `/memory decision <text>`: append `decision` event
- On `/memory note <text>`: append `note` event

### Source Naming

Consistent with existing `event-factory.ts`: `adapter.codex`, `adapter.claude`, `engine`, `user`.

### Compaction

No compaction in v0.3. Log is strictly append-only, no delete or mutation. Archive/compaction deferred to v0.4.

## Section 2: Worktrees MVP

### WorktreeManager (`internal/worktree/manager.ts`)

```typescript
interface WorktreeManager {
  create(agentName: string, branchName?: string): Promise<WorktreeInfo>;
  list(): Promise<WorktreeInfo[]>;
  remove(agentName: string, force?: boolean): Promise<void>;
  getForAgent(agentName: string): Promise<WorktreeInfo | null>;
  status(agentName: string): Promise<WorktreeStatus>;
  ensureClean(agentName: string): Promise<boolean>;
  reconcile(): Promise<void>;  // startup reconciliation
}
```

#### WorktreeInfo

| Field | Type | Description |
|-------|------|-------------|
| `agentName` | string | agent bound to this worktree |
| `path` | string | absolute path to worktree directory |
| `branch` | string | branch name (e.g. `agoryx/codex-task-42`) |
| `createdAt` | string | ISO timestamp |

#### WorktreeStatus

| Field | Type | Description |
|-------|------|-------------|
| `clean` | boolean | no uncommitted changes |
| `ahead` | number | commits ahead of default branch |
| `behind` | number | commits behind default branch |
| `conflicted` | boolean | merge conflicts exist |

### Git Operations

- Create: `git worktree add .agoryx/worktrees/<agent> -b <branch>`
- List: `git worktree list --porcelain`
- Remove: `git worktree remove .agoryx/worktrees/<agent>`
- Worktrees live under `.agoryx/worktrees/` (gitignored)

### Directory Setup

- Add `.agoryx/` to `.gitignore` at repo root
- Worktrees, memory.md, and other runtime artifacts live under `.agoryx/`

### Startup Reconciliation

On process start: `git worktree list --porcelain` → compare with `memory_snapshot.active_worktrees` → auto-recover agent-worktree map after crash or manual git operations.

### Guardrails

1. **One agent per worktree** — `create()` rejects if agent already has active worktree (idempotent: returns existing if same params)
2. **One worktree per agent** — strict 1:1 binding
3. **No cross-write** — adapter `workspaceCwd` always points to agent's own worktree
4. **Fail on dirty** — `remove()` fails if worktree has uncommitted changes; explicit `--force` required for override
5. **Manager lock** — mutex prevents race conditions from parallel create/remove calls

### Base Branch

`ahead`/`behind` computed against default branch (`origin/HEAD` with fallback to `main`/`master`), not hardcoded to `main`.

### Engine Integration

- Team mode: `startTeamRun()` auto-creates worktrees for each agent if not present
- `shutdown()` does NOT auto-remove worktrees (user decides when to clean up)
- `workspaceCwd` set per-dispatch in team runtime (not global config drift)

### Storage

Worktree state persisted in `memory_log` events (`worktree_create`, `worktree_remove`) + reflected in `memory_snapshot.active_worktrees`.

### Out of Scope (v0.3)

- Auto-rebase/auto-merge
- Conflict resolution policy
- Multiple worktrees per agent

## Section 3: Workspace Context

### WorkspaceCollector (`internal/workspace/collector.ts`)

```typescript
interface WorkspaceCollector {
  collectAlwaysOn(cwd?: string): Promise<WorkspaceContext>;
  collectOnDemand(cwd?: string): Promise<WorkspaceExtended>;
  format(ctx: WorkspaceContext): string;
}
```

### Always-On Context (every dispatch)

| Field | Source | Budget |
|-------|--------|--------|
| `branch` | `git rev-parse --abbrev-ref HEAD` | ~20 chars |
| `status` | `git status --short` | top N lines (configurable) |
| `diffSummary` | `git diff --stat` (unstaged) + `git diff --cached --stat` (staged) | top N lines |
| `fileTree` | `git ls-files` + limited untracked list | top N lines |
| `pinnedDocs` | `CLAUDE.md`, `AGENTS.md` from workspace root | hard cap per file + `[truncated]` |

### On-Demand Context

| Field | Source |
|-------|--------|
| `recentCommits` | `git log --oneline -20` |
| `headVsMain` | `git diff --stat <default-branch>...HEAD` |

### Configuration

```json
{
  "workspace": {
    "enabled": true,
    "maxContextTokens": 3000,
    "statusLines": 50,
    "diffLines": 30,
    "treeLines": 200,
    "pinnedDocBytesPerFile": 4096
  }
}
```

### Prompt Injection

Workspace context prepended as `[Workspace]` block before agent messages:

```
[Workspace]
Branch: feat/memory-core
Status: M internal/storage/sqlite.ts, ?? internal/workspace/
Staged: A internal/worktree/manager.ts
Diff: 3 files changed, 142(+), 12(-)
Tree: (200 lines, truncated)
---
```

### Injection Points

1. `buildContext()` — legacy/cli path (already injects pinned context; workspace goes before pins)
2. `buildDeltaPrompt()` — persistent/agentic warm path (must inject workspace into delta prompt)
3. `buildTeamPrompt()` — team runtime (inject with actor's worktree cwd)

### Worktree Awareness

When agent has a worktree, `collectAlwaysOn()` runs against worktree's cwd. Each agent sees their own workspace state.

### Cache Invalidation

Invalidate workspace context cache:
- After each completed dispatch
- After worktree create/remove
- On new user message

### Degraded Mode

If `git` is unavailable or cwd is not a repo: return `[Workspace unavailable: <reason>]` instead of failing dispatch.

## Section 4: CLI Surface

### Command Grammar

Explicit subcommand structure for unambiguous parsing:

```
/memory show               — display current snapshot
/memory decision <text>    — record a key decision
/memory note <text>        — record a free-form note
/memory log [limit] [--source X] [--type Y] [--since ISO] [--json]
/memory rebuild            — force full replay (under room lock)
/memory render             — force .agoryx/memory.md regeneration

/workspace show            — display always-on context
/workspace full            — display always-on + on-demand context
/workspace show --json     — JSON output

/worktree list [--json]    — all worktrees with agent binding + status
/worktree create <agent> [branch]
/worktree remove <agent> [--force]
/worktree status [agent] [--json]
```

### --json Support

All new commands support `--json` flag for machine-readable output (Predictable Output goal).

### /memory rebuild

Executes under room lock. Returns explicit result: `{ processed, deduped, snapshot_version, duration_ms }`.

### /memory log

Supports filters: `--source`, `--type`, `--since`. Default sort: `id DESC`. Default limit: 20.

### /team log Enhancement

Split output into two sections/flags:
- `--steps` (default) — team step history
- `--memory` — memory log events
- No flag — both sections

### Enhanced /team status

Now includes: worktree info + workspace summary per agent.

### /help Update

All new commands added to `/help` output. Command-handler tests required for each new command.

## Section 5: `.agoryx/memory.md` Autogen

### Canonical Path

`<workspace-root>/.agoryx/memory.md` — only in root workspace, never in agent worktrees.

### Generation Triggers

- After each checkpoint (engine auto-snapshot)
- After semantic events: `decision`, `note`, `worktree_create`, `worktree_remove` (with 1-2s debounce)
- On `/memory render`

### Atomic Write

Write to temp file, then rename. Prevents torn reads.

### Header

```markdown
<!-- AUTO-GENERATED by Agoryx. DO NOT EDIT. -->
# Agoryx Project Memory
Generated: 2026-02-19T10:00:00Z | Room: room_abc
```

### Format

```markdown
<!-- AUTO-GENERATED by Agoryx. DO NOT EDIT. -->
# Agoryx Project Memory
Generated: <timestamp> | Room: <room_id>

## Current State
- **Goal:** <current_goal>
- **Branch:** <active_branch>
- **Worktrees:** <agent → path (branch)>

## Key Decisions
- <decision 1>
- <decision 2>

## Blockers
- <blocker or "(none)">

## Next Actions
- <action 1>

## Recent Log (last 10)
| Time | Source | Event | Summary |
|------|--------|-------|---------|
| ... | engine | dispatch_end | codex: done, 3 files |
```

### Gitignore

`.agoryx/` is gitignored — `memory.md` is autogenerated and not version-controlled.

## Out of Scope for v0.3

1. Web UI (including read-only timeline)
2. Full MCP transport
3. Auto-rebase/auto-merge for worktrees
4. Conflict resolution policy
5. Rich memory (snippets, deep dependency analysis)
6. Log compaction/archival
7. Deep workspace analysis (import graphs, module structure)
